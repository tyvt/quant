# 多股类与库存股证券的证券池排除语义：独立评估提案

状态：**讨论稿，未获批准，未生效**。日期：2026-10-01。
基线：`RULE_SPEC v1.3.1` 的点时证券池、`NEEDS_REVIEW` 全月门槛和
`GENERAL_FCF_MONTHLY_TOP20_V1`。本稿不修改现行规则、代码、配置、
manifest 或真实运行授权；亦不代替[暂行保守解释提案](2026-10-01-historical-shares-fail-closed.md)。

## 为什么需要独立裁决

现行证券池先纳入主板有效区间的沪深 A 股，再检查股本等输入。
股本口径未裁决时，证券为 `NEEDS_REVIEW`，任何一只都会使整月仅能出诊断。
直接改用 `REJECTED` 会把“未知”谎称为“已知硬门失败”；直接改用
`NOT_SUPPORTED` 则混淆现有的行业 Profile 不支持语义。两份 PDF 探针
不能代表全市场历史发生率，当前也不具备真实选股/回测授权，不能据此
宣称实际有多少月份会被阻断。

## 可选政策与取舍

| 方向 | 精确定义 | 后果 |
| --- | --- | --- |
| A：维持现状（当前推荐） | 多股类或非零库存股口径未决时，`S/MV=UNKNOWN`；保留在池中并标记 `NEEDS_REVIEW` | 完整性最强；可能长期只有诊断，不产生官方 Top-N |
| B：显式政策排除（仅供未来审议） | 在计算候选前，按版本化规则和**点时已证实**的股类/库存股状态标记独立的 `POLICY_EXCLUDED`；未知状态仍为 `NEEDS_REVIEW` | 可使剩余证券形成官方候选，但研究对象变为“政策限定的子池”，结果不再与原策略直接可比；需单独披露选择偏差 |
| C：跳过未知证券后继续官方排序（不建议） | 保持原池，却忽略其中 `NEEDS_REVIEW` 的证券 | 违反当前全月门槛，且会以数据缺失决定入选机会；不得在 v1.3.1 下实现 |

方向 B **不是**把未知证券静默改名为 `REJECTED`/`NOT_SUPPORTED`；必须重新定义
结构证券池的资格边界、何时可证实“已知多股类/库存股”、何时恢复资格、
库存股账户消失或股份注销时如何更新，以及未知/证据缺失仍如何硬阻断。
除非项目负责人明确批准，方向 A 持续有效。

## 若选择方向 B，正式提案至少需要

1. 明确排除对象和日期语义：多股类是否一律排除；库存股是只要非零就
   排除还是按金额/股份比例；证据可用日与事件生效日分别计算；历史退市
   证券和后续股类变更如何保留。不能以当前状态回填历史。
2. 量化并披露选择偏差：在**已授权的数据覆盖审计**中逐月报告原结构池数、
   政策排除数、未知数、可评估数，按行业/规模/年份拆分。不能用本次两只
   证券推断全市场影响，也不能先看回测业绩再调排除口径。
3. 定义可追溯输出：逐证券保存 `security_id`、`as_of`、排除原因、规则版本、
   点时证据引用和来源快照 ID；官方候选表/诊断报告必须区别
   `POLICY_EXCLUDED` 与真正 `NEEDS_REVIEW`，不能把前者伪装成市场硬门失败。
4. 升级配置和运行身份：冻结 `universe_policy_id`、政策版本和排除记录的
   canonical 内容哈希；`RunManifest`/`StrategyRunManifest` 应可引用该哈希、
   输入快照和覆盖摘要。现有 `StrategyRunManifest` 的 schema 与
   `rules_version=v1.3.0` 校验被冻结，不能直接覆写旧 manifest 或旧运行。
5. 做确定性与逆向测试：同一证据重复运行哈希一致；仅未来才公布的股类/
   库存股信息不可影响过去；政策排除与未知证据互不混淆；一只真正
   `NEEDS_REVIEW` 仍使整月诊断；排除证据被篡改时硬失败。

方向 B 会改变证券池与决策语义、影响历史可比性，按当前版本规则应提出
**MAJOR** 级正式修订，并单独确定新策略 ID、迁移/不可比结论和批准前
提案哈希。当前没有足够覆盖证据或授权来批准它；本稿只启动问题评估。
